# 协作弹窗选择老师交互设计

## 目标

降低邀请协作者时的操作层级和理解成本，同时保留适合校园场景的“全校”与“同学科”批量选择能力。

## 现有问题

- “选择校内老师”与展开后的搜索框重复表达同一任务。
- 候选名单展开后常驻且推挤页面，让弹窗显得过长。
- “收起名单”是为容器状态设计的操作，不是用户任务。
- 批量选择外观与筛选标签过于相似，容易产生误解。
- 待选人、权限与最终添加动作的视觉连续性不足。

## 方案

### 选人器

- 将外层下拉入口和内层搜索框合并为一个可搜索多人选择器。
- 未选择时显示占位文案“搜索姓名”；点击或获得焦点后打开候选浮层。
- 候选项仅展示老师姓名，不补充学科、年级或其他身份信息。
- 候选项使用 checkbox 语义；选中多人时浮层保持打开。
- 已选老师在输入区内显示为可移除标签，保留不超过现有容器高度的内部滚动。
- 已在协作列表中的老师保持不可选，并标注“已加入”。

### 批量选择

- 保留“全校全部成员”和“同学科全部成员”。
- 两个入口放在候选浮层中，作为明确的批量动作，不表现成筛选分类。
- 按钮显示可选人数；当该组全部选中时显示已选状态，再次点击取消该组选择。
- 已加入的协作者不计入可选数量，也不会被批量操作改变。

### 添加和权限

- 权限选择与主操作继续处于同一操作行。
- 主按钮在已选人数不为零时显示“添加 N 位老师”，点击后一次性赋予当前所选权限。
- 添加成功后清空待选集合、关闭候选浮层，并在“协作成员”中立即显示新成员。
- 保留现有的权限说明、成员权限修改、成员移除和 toast 反馈。

## 键盘与关闭行为

- `ArrowDown` 从搜索框进入第一个可选候选项。
- 候选项间使用 `ArrowUp` / `ArrowDown` 循环移动。
- `Enter` 或点击切换候选项，不关闭浮层。
- `Escape` 优先关闭候选浮层，再次按下由原生 dialog 关闭弹窗。
- 点击选人器以外的区域关闭候选浮层，但不清空已选老师。

## 范围与验收

仅修改 `collaboration.js` 和 `collaboration.css`，不改成员权限数据结构、本地存储 key、复制链接或评论流程。

验收包括：单人搜索选择、多人连续选择、全校批量选择与取消、同学科批量选择与取消、已加入成员禁用、标签删除、权限切换、添加成员、点外关闭、`Escape` 关闭和键盘方向键导航。
